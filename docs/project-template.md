# 프로젝트 제목

> 상태: 기획 / 구현 중 / 검증 중 / 공개 완료 중 하나를 선택하세요.

## 한 문장 소개

누가 어떤 상황에서 겪는 문제를 어떻게 해결하는가?

## 문제와 목표

- 기존 방식과 불편:
- 이번 구현의 범위:
- 완료 조건:

## 결과물

- 코드 또는 제작 파일:
- 데모 또는 화면 기록:
- 입력 예시:
- 출력 예시:

## 구현과 나의 역할

- 사용 도구·모델·버전:
- 처리 흐름:
- AI에 맡긴 작업:
- 직접 설계·검토·수정한 작업:
- 이 방식을 선택한 이유:

## 검증

| 사례 | 기대 결과 | 실제 결과 | 판정 및 근거 |
| --- | --- | --- | --- |
| 정상 입력 | 작성 예정 | 미측정 | 미검증 |
| 정보 부족 | 작성 예정 | 미측정 | 미검증 |
| 오류 입력 | 작성 예정 | 미측정 | 미검증 |

측정 날짜, 데이터 범위, 실행 환경, 비교 기준, 응답 시간과 비용을 적습니다.
미측정 항목은 미측정으로 유지합니다.

## 업무 자동화에 적용한 경우

- 기존 작업의 입력·빈도·수작업 단계:
- 자동화한 단계와 사람이 검토한 단계:
- 같은 입력으로 측정한 수작업 시간:
- 실행·검토·수정을 포함한 자동화 후 시간:
- 측정 횟수와 품질 비교 결과:

실제 적용 전이면 기획으로 표시하고, 측정하지 않은 성과는 기재하지 않습니다.

## 실패와 개선

실패 입력, 원인 가설, 변경 사항, 변경 후 확인 결과를 적습니다.

## 재현 방법

필요한 환경, 설치·실행 명령, 샘플 데이터, 예상 결과를 적습니다.
계정 정보와 비밀 키 대신 환경 변수 이름과 설정 방법만 설명합니다.

## 배운 점과 다음 실험

직접 확인한 사실과 아직 확인하지 못한 가설을 나눠 적습니다.

## 참고 자료

원문 링크, 확인 날짜, 참고한 부분을 적습니다.
